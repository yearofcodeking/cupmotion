# Материалы: логотипы, иконки, картинки, музыка, голос

По умолчанию ролик целиком свой: рисунок кодом, звук синтезируется под него (`sound.md`). Внешний материал берётся, **только если делает ролик лучше**:
настоящий логотип бренда, фотография, живая озвучка. Скачивание и установка — с разрешения пользователя.

## Логотипы брендов
Настоящий знак компании не перерисовывать «по памяти». Брать официальный SVG: сайт бренда, press kit, у организации — её аватар на GitHub, в крайнем случае favicon.
Нет под рукой — сказать об этом и спросить файл, а не рисовать похожий. Иконки — из настоящего открытого набора с проверенной лицензией; эмодзи и `div`, стилизованный под иконку, в ролик не идут.

## Каталог материалов: media-use
Если в окружении пользователя стоит навык `media-use` (HyperFrames), он находит музыку, звуки, картинки, иконки, логотипы и голос одной командой:
```
npx hyperframes media-use resolve --type <bgm|sfx|image|icon|logo|voice> --intent "<описание>" --project <папка>
```
Результат — файл в проекте и запись в журнале (повторный запрос возьмёт уже найденное). Первый запуск: установить и войти в `heygen` CLI (`npx hyperframes media-use resolve --doctor` проверит).
Озвучка через вход по OAuth даёт бесплатный лимит, по API-ключу тратит кредиты — сказать пользователю **до** генерации. Лицензию трека проверить до публикации ролика **[оценка]**.
Навыка нет — не ставить без просьбы: каталоги из `sound.md` и `sites.md` и свой синтез закрывают то же самое.

## Один проход «что здесь просится» (раз за проект)
Предлагать только по конкретному признаку и **одним сообщением**, а не молча добавлять и не дёргать по каждому файлу:
- на экране текст или сценарий, а озвучки нет — голос;
- иконка нарисована эмодзи или блоком — настоящая иконка;
- картинка-заглушка, мелкая или растянутая — лучше исходник;
- ролик длиннее ~10 с без музыкальной подложки — подложка (свой синтез или каталог);
- смена места без звука — акцент на стыке (склеек в cupmotion нет, поэтому звук ставится на движение, переносящее в новый мир).
Нет признака — нет предложения. Отказ пользователя — не повторять.

## Цвет чужого футажа
Автоматически «исправлять» цвет чужой записи нельзя: серый баланс убивает закат и неон. Сначала показать до/после на одном кадре, применять только принятое.
Цифровой LUT — только готовый файл `.cube` от пользователя; не генерировать LUT ради экспозиции или контраста.

## Дизайн из Figma
Ссылка `figma.com` в запросе: ассеты, цвета и шрифты брать из файла по REST-API, токен `FIGMA_TOKEN` с доступом только на чтение, **в чат токен не вставлять**.
Кадры раскадровки в Figma — состояния одной сцены, а не слайды: движение между ними достраивается, как в `continuity.md`.

Идеи: навык media-use и навык figma из heygen-com/hyperframes (Apache-2.0), переписаны.
